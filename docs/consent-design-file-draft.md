# Черновик: согласие и политика для файла дизайн-проекта

Статус: **на утверждении**. Пока тексты не утверждены, поле «Прикрепить дизайн-проект» на главной выключено (`DESIGN_FILE_UPLOAD_ENABLED = false` в `client/src/pages/Home.tsx`). Серверная часть уже готова и принимает файл только вместе с заявкой.

Почему нужна новая редакция: действующие тексты (версия `2026-10-04`) называют только «имя, телефон и параметры запроса». В файле проекта могут быть адрес квартиры, планировка, ФИО собственника и другие сведения, которые пользователь сам решит передать. Их передача в Telegram должна быть прямо названа в обоих согласиях и в политике.

Изменения выделены **жирным**.

## 1. Отметки в форме (`PersonalDataConsent.tsx`)

Первая отметка:

> Даю согласие ИП Бережному Егору Юрьевичу на обработку моих персональных данных — имени, телефона, параметров запроса **и сведений в приложенном мной файле (если я его приложил)** — для приёма, регистрации и ответа на заявку. С условиями ознакомлен(а) в Политике обработки персональных данных и тексте согласия.

Вторая отметка:

> Даю согласие на передачу указанных в заявке данных **и приложенного файла** через мессенджер Telegram для оперативного уведомления оператора о моём обращении. Порядок передачи и возможные риски описаны в Политике обработки персональных данных.

Подсказка под полем загрузки (новая, мелким текстом):

> Файл увидит только команда «Классного ремонта». Не прикладывайте паспортные данные и другие документы, не нужные для расчёта.

## 2. Политика обработки (`Legal.tsx`, `PrivacyPolicy`)

Раздел 2, новая строка таблицы:

| Данные | Цель | Основание |
|---|---|---|
| **Файл дизайн-проекта или планировки (по желанию пользователя)** | **Учесть проект при расчёте стоимости и подготовке к замеру** | **Согласие пользователя** |

Раздел 3, добавить в конец:

> **Приложенный к заявке файл хранится на сервере Оператора только до его передачи Оператору через Telegram и затем удаляется с сервера; дальнейшая обработка ведётся в пределах цели обращения.**

Раздел 4, первое предложение:

> После отдельного, необязательного для иных способов связи согласия пользователя сведения из заявки — имя, телефон, параметры запроса **и приложенный пользователем файл** — направляются в Telegram для оперативного уведомления Оператора.

## 3. Текст согласия (`Legal.tsx`, `PersonalDataConsentPage`)

Раздел 1, перечень данных:

> …согласие на обработку имени, номера телефона, параметров запроса: выбранной услуги, площади, жилого комплекса и предварительных расчётных данных, **а также сведений, содержащихся в файле дизайн-проекта или планировки, если пользователь его приложил**.

Раздел 2:

> …пользователь отдельно соглашается на передачу имени, телефона, параметров заявки **и приложенного файла** через Telegram для оперативного уведомления Оператора.

## 4. Что сделать после утверждения (техническая часть, сделаю сам)

1. Новая версия согласия — дата утверждения, например `2026-10-XX`: `PERSONAL_DATA_CONSENT_VERSION` в `PersonalDataConsent.tsx`, перечень допустимых версий в `server/routers.ts` и `server/telegram.ts` (предыдущая `2026-10-04` остаётся допустимой для уже открытых страниц).
2. Тексты из разделов 1–3 выше.
3. `DESIGN_FILE_UPLOAD_ENABLED = true`.
4. Серверу — принимать файл только с новой версией согласия.
5. Обновить тесты `Legal.compliance.test.ts` и `Home.feedback.test.ts`.
6. На сервере выложить новые конфиги Nginx (`deployment/*.nginx.conf`) и выполнить `sudo nginx -t && sudo systemctl reload nginx` — иначе файлы больше 5 МБ не пройдут.
7. По `deployment/OPERATIONS.md` — уведомление Роскомнадзора о трансграничной передаче уже упомянуто в политике; проверить, что в нём указан и состав данных с файлами.
